h3. Added

* *Option to disable thinking mode for AI summaries*, centrally and per project (use central setting / disabled / allowed). A reasoning model behind the custom provider could spend its whole output budget on reasoning and return an empty answer, so the ticket got no summary. When disabled, summary requests send @chat_template_kwargs: {"enable_thinking": false}@ (vLLM/SGLang, e.g. Qwen3). Only the custom provider sends it; OpenAI and Anthropic requests are unchanged. Also available in the project settings API as @ai_summary_disable_thinking@.
* *Warning in the settings.* Both settings pages warn when thinking is off while knowledge-base proposals go into the summary: without reasoning the model added an unfitting or empty solution proposal in 9 of 20 test tickets (0 with thinking).
* *Summaries retry once on an empty answer.* With thinking allowed and the custom provider, an empty answer is asked again with thinking off and without the knowledge-base block. The note says so, and the sidebar proposals keep no verdict for that run. Other errors are not retried.

h3. Upgrade notes

Migration 066 adds the per-project thinking column - run the migration command. Nothing changes until the option is enabled: thinking stays allowed by default. For reasoning models (e.g. Qwen3) set the maximum output tokens of the AI summary to at least 5000; with low limits the reasoning alone uses up the budget.
